# LineMedic v4 — 진행 불가 보고서

> **빈 양식. 실제 알림 전송본이 아니다.** [16 알림 계약](../docs/16-notifications.md)에 따라 host가 관찰 사실로 채운다. 모델 API가 실패해도 이 양식을 작성할 수 있어야 한다.

## 1. 식별·알림

| 항목 | 입력 |
|---|---|
| run / incident / work / generation / attempt | 실제값, 생성 전이면 해당 없음 |
| repo / Issue | 실제 연결값; 연결 실패이면 미연결 |
| blocker_code / stage | 고정 분류와 실제 실패 단계 |
| 관찰 시각 | UTC RFC3339 |
| 담당 route ID | host catalog에서 선택, 원문 주소 미기록 |
| notification ID / 상태 / receipt | PENDING / SENDING / ACCEPTED / FAILED / UNKNOWN |
| 마지막 외부 실행 ID·상태 | 실제값, 없으면 NONE |

## 2. 보고 본문

**현재 현상과 영향:** 관찰한 오류·사용자 증상. 추정 영향은 추정이라고 표시한다.

**진행하지 못한 이유:** 지원 범위, 논리적 충돌, 자료 부족, 권한 부족, 사람 작업 충돌, 모델/API 장애 중 정확한 사유. 해결하지 못했는데 완료 표현을 사용하지 않는다.

**확인한 근거:** evidence ID, 관찰 시각, 해당 source. 근거가 없으면 없다고 적는다.

**실제로 해본 일:** 읽기·테스트·변경·외부 요청 각각 실제 실행 결과를 기록한다. 제안만 하고 수행하지 않은 일은 별도 단락에 둔다.

**수행하지 않은 일:** 미배포·미머지·DB 미변경·설비 미제어 등 실제 확인된 범위만 적는다.

**현재 부작용 상태:** NONE / OBSERVED / UNKNOWN. timeout을 ‘변경 없음’으로 단정하지 않는다. 실제 Issue/PR/image/notification identity를 붙인다.

**담당자에게 필요한 조치:** 필요한 자료·승인·정책 결정·지원 시스템 담당자의 확인. 현장 조작 명령이나 무조건적인 삭제·권한 확대를 권고하지 않는다.

**다시 시작할 조건:** 무엇이 달라져야 하는지 명시한다. 조건 해소 후 operator 승인 → 새 generation → 새 시작 알림으로 처리한다.

## 3. 검수

- [ ] 사람 수신자를 로그·Issue·모델이 지정하지 않았다.
- [ ] raw secret·개인정보·원문 전체 로그·임의 외부 링크가 없다.
- [ ] 실제 동작과 미실행 제안을 구분했다.
- [ ] 실행 불명과 알림 미전송을 숨기지 않았다.
- [ ] Issue를 무단 close하거나 incident를 RESOLVED로 바꾸지 않았다.
- [ ] 발송했다면 공급자 receipt가 있으며 사람의 열람을 보장하지 않았다.

알림 전송과 같은 사건의 case note 작성은 별개다. 권한 부족은 BLOCKED 사례이지 검증된 오답 코드가 아니다.
